# Газетная мастерская

Статический редактор печатной газеты в духе середины и конца XIX века. Демо — «Валенарский вестник». Название, дата, город, номер и цена свободно меняются; календарь может быть вымышленным.

## Запуск

Откройте **index.html** в современном браузере. Для локального сервера, если установлен Node.js:

```sh
npm start
```

Адрес: http://127.0.0.1:4173. Установка зависимостей для работы сайта не нужна. Исходный файл `0HgUcdWYTFqviyGPL.html` сохранён без изменений для справки.

## Что умеет редактор

- Статьи, короткие заметки и объявления с отдельным редактированием.
- Полужирный, курсив, подчёркивание, списки, цитаты, буквицы и выравнивание.
- Автор, рубрика, иллюстрация JPG/PNG/WebP, подпись. Изображения в газете чёрно-белые, исходный цвет сохраняется в проекте.
- От 1 до 4 колонок, ширина отдельного материала, порядок материалов и дубликаты.
- A4/A3, размер текста, цвет бумаги и виньетки. Переполненные материалы продолжаются на следующих страницах.
- Газетный предпросмотр, масштабирование; на телефоне — вкладки материалов, макета и оформления.
- Автосохранение выпуска в браузере, отмена и повтор изменений.
- Скачивание PDF, JSON и Markdown; импорт JSON и Markdown.

Изменения в окне материала попадают в выпуск по кнопке **«Применить»**; **«Отмена»** закрывает черновик. Стрелки в списке меняют порядок материалов; ширину выбирайте в редакторе статьи. При уменьшении числа колонок материал временно занимает не больше ширины полосы. Размещение идёт по порядку в свободную область с наименьшей высотой; широкие статьи занимают несколько соседних колонок. Очень длинная статья продолжается в следующей свободной колонке, затем на новом листе с повтором заголовка.

## Сохранение и перенос

**JSON — основной формат проекта.** Он содержит тексты с оформлением, изображения и параметры газеты. Скачайте его через «Экспорт» и откройте на другом устройстве через «Открыть выпуск». Для замены текущего выпуска редактор показывает подтверждение и предлагает сначала скачать резервную копию. Замену можно отменить.

**Markdown** содержит читаемые статьи и скрытый снимок проекта в комментарии. Обратный импорт такого файла восстанавливает снимок целиком. Если вы редактируете Markdown во внешнем редакторе и хотите импортировать именно изменённый текст, удалите комментарий со снимком в конце файла: тогда будут импортированы заголовки и текст, без исходных параметров макета. Обычные `.md` без снимка тоже поддерживаются.

Автосохранение относится к одному браузеру и адресу сайта. Это не облачная синхронизация. Если хранилище браузера заполнено или запрещено, редактор сообщит об этом; скачайте JSON. Изображения сжимаются при загрузке до 1800 пикселей по большей стороне. В одном выпуске допускается до 200 материалов, импортируемый файл — до 30 МБ. Рекомендуется периодически скачивать резервную копию.

Сочетания клавиш: `Ctrl/Cmd+S` — JSON; `Ctrl/Cmd+Z` — отмена; `Ctrl/Cmd+Shift+Z` — повтор. Внутри текстового поля работают стандартные сочетания редактирования и его собственная история отмены.

## PDF и печать

Кнопка **«Экспорт → Готовая газета»** создаёт и скачивает многостраничный PDF прямо в браузере. Страницы сохраняются как изображения (A4 — 216 dpi, A3 — 168 dpi), благодаря чему сохраняется кириллица и газетное оформление, в том числе на телефоне. Текст в таком PDF не выделяется. Для больших выпусков экспорт может занять время; прогресс показывается в окне.

Для **PDF с выделяемым текстом** или обычной печати нажмите **«Печать»**, затем выберите принтер либо «Сохранить как PDF». Укажите тот же формат бумаги, что в редакторе, масштаб 100%, поля «Нет» и отключите колонтитулы браузера. Для цветной бумаги включите печать фона. Для экономии чернил выберите «Белая · для принтера» в настройках редактора. Системное окно печати и способы сохранения отличаются в разных браузерах и ОС.

Макет, обычная печать и PDF используют одинаковую разбивку по страницам. Если материал нельзя разместить, редактор сообщает об ошибке и не экспортирует устаревший макет.

## GitHub Pages

1. Создайте репозиторий на GitHub.
2. Загрузите в корень `index.html`, `styles.css`, `app.js`, `document.js`, `pagination.js`, `.nojekyll`, папки `assets` и `vendor` целиком. Можно также загрузить весь проект, кроме временной папки `tmp` и `node_modules`.
3. Откройте **Settings → Pages → Build and deployment**.
4. В **Source** выберите **Deploy from a branch**, ветку с файлами (обычно `main`) и папку **/(root)**; нажмите **Save**.
5. После публикации откройте адрес, показанный в Pages.

Все пути относительные: сайт работает и по адресу `https://имя.github.io/репозиторий/`. Сервер приложения, API, база данных, токены и сборка не нужны. Сам сайт не отправляет материалы на сервер. Шрифты и библиотеки хранятся локально; их лицензии находятся рядом с файлами.

[Инструкция GitHub по источнику публикации](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Файлы и проверки

- `index.html` — интерфейс и диалоги.
- `styles.css` — оформление интерфейса, газетной полосы, телефона и печати.
- `document.js` — модель выпуска, проверка данных, очистка HTML, JSON/Markdown.
- `pagination.js` — физические размеры и размещение на печатных страницах.
- `app.js` — редактирование, история, хранилище браузера, экспорт и импорт.
- `assets/fonts` — шрифт Old Standard с кириллицей, три начертания.
- `vendor` — зафиксированные локальные версии html2canvas и jsPDF, лицензии.
- `scripts/serve.cjs` — вспомогательный локальный сервер для разработки.
- `tests` — проверки данных и браузерных сценариев.

Для разработки и браузерных проверок установите зависимости:

```sh
npm install
npx playwright install chromium
npm test
```

Это инструменты разработки; GitHub Pages они не нужны. При установленном Chrome можно задать `BROWSER_CHANNEL=chrome`; `PLAYWRIGHT_PATH` позволяет указать путь к уже установленному пакету Playwright.
